# 重复标签页筛选设计

## 交互选择

在现有筛选栏中加入一个单独的 `Duplicates` 按钮，采用与 `aria-pressed` 兼容的 toggle button，而不是再增加一个下拉框。原因是这个筛选只有启用和停用两种状态，按钮可以直接表达当前状态，也不会把“重复”误解为一种互斥的分类。按钮放在搜索框之后、窗口范围之前，作为筛选条件的一部分；启用后使用选中态视觉样式，并以 `aria-pressed="true"` 暴露状态。

按钮只负责改变视图，不触发选择或批量操作。搜索、窗口范围、分组状态、固定状态和分组筛选仍然可以继续组合。筛选栏中的其他条件会缩小最终展示结果，但重复关系基于当前完整的 `BrowserSnapshotView` 计算，这样在“当前窗口”范围下仍然可以发现当前窗口中的标签页与其他窗口标签页重复的情况。

## 检测模型

在 `src/domain/filters.ts` 附近增加独立的重复检测模块，使用可扩展的策略接口：

- `DuplicateDetectionStrategy` 描述一个策略标识和从标签页生成匹配 key 的函数。
- 策略返回 `undefined` 时表示该标签页不参与该策略。
- 对同一策略生成相同 key 且出现次数至少为 2 的标签页，全部加入重复标签页集合。
- 多个策略使用 OR 关系合并结果；因此初始的 URL 策略或标题策略任一命中，标签页就会被视为重复。

初始策略只使用非空的 `url` 和 `title`，对值执行 `trim()` 后进行精确匹配，不做大小写折叠、URL 规范化或站点语义推断。这样不会提前固定未来站点专用规则的行为。后续可以增加按 hostname 选择策略、URL 规范化、页面内容标识或站点级业务键，而不需要修改筛选栏和渲染组件。

## 过滤顺序

`applyTabFilters` 先根据完整视图和默认策略得到重复标签页 ID 集合，再把 `duplicatesOnly` 作为普通过滤条件应用到最终标签页列表。未启用时不计算或不影响结果；启用但没有重复项时，沿用现有空状态表现，不新增特殊页面。

筛选逻辑继续通过 `createBrowserSnapshotView` 重建窗口和原生分组跨度，保证重复筛选不会破坏原生标签页顺序和分组呈现。

## 测试边界

领域测试覆盖：URL 重复、标题重复、同一标签页同时命中两个策略、空 URL/空标题不产生重复、跨窗口重复，以及与现有窗口/分组/固定状态筛选的组合。组件测试覆盖按钮的 `aria-pressed` 状态和点击后结果变化；构建校验负责确认 TypeScript 与 WXT 入口仍可编译。
