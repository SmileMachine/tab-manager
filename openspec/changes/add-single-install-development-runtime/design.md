## 目标与已批准决策

同一份本地安装扩展：启动开发后自动接入 WXT/Vite HMR，正常结束开发后自动恢复独立运行，不安装第二份扩展，也不要求每次手动重新加载。

用户在 2026-10-25 同意复用现有 Native Messaging host，并要求明确发行边界。本方案据此替代此前的本地标记轮询：不增加定期检查、不增加 `alarms` 权限，不保留静默回退到轮询或手动重载的路径。

host 负责开发模式切换通知，不负责 React 页面热更新；开发期间的 HMR 仍由 WXT/Vite 完成。

## 当前源码与环境证据

- WXT 开发页面从 localhost 加载页面模块；默认独立构建则是完整本地资源。
- WXT 的 `reloadExtension()` 通过开发 WebSocket 通知后台；独立构建没有该连接，无法单靠这个接口自动进入开发模式。
- 后台在 `src/background/index.ts` 无条件调用 `connectNativeCodexBridge()`；`src/codex/nativeMessaging.ts` 的默认重连延迟是 1000 ms。发行前需要将此生命周期改为显式启用，而不是只从构建里删除开发控制代码。
- 先前只读现场检查确认：本机 Edge 注册了 `com.shawn.tab_group.codex`，授权 ID 对应当前 `.output/edge-mv3-dev/`；host 是 Edge 的活跃子进程。当时未发现已连接的 Codex MCP peer。
- 现有 host 与扩展协议只处理已有 RPC 等消息，尚不具备本方案所需的独立开发控制能力。运行中的现有 host 也不会因磁盘代码更新而自动获得新协议，需要考虑一次性迁移。
- 此前临时 Edge 实验仅验证了轮询标记的自动重载，不证明 host 主动通知方案可用；该实验不是本方案的集成验收。

## 三种运行场景的边界

| 场景 | host 要求 | 连接策略 | 开发切换能力 |
| --- | --- | --- | --- |
| 本地自用包：开发及退出后的日常运行 | 自动开发切换需要本机已安装且授权的 host；正常标签管理本身不依赖它 | 本地自用模式可自动建立受限开发连接 | 有，仅本地模式 |
| 普通发行用户 | 不需要 host、Node.js 或开发服务 | 默认不连接 host、不安排重试 | 无 |
| 发行用户主动启用本地 Codex/MCP | 需单独安装并授权 host | 显式启用后连接，失败清晰提示；关闭后断开并停止重试 | 无，不能通过可选业务桥接启用开发控制 |

这三种场景不是要求用户装三个包。本地开发者仍只维护一份安装，发行用户只安装正常扩展；可选业务桥接通过明确设置启用。

### 发行包的具体要求

- 保留完整独立的标签页与标签组管理能力，没有 host 时正常使用。
- 编译产物不包含本地开发控制监听、开发控制入口或针对本地开发 host 的自动连接逻辑。
- 可选 Codex/MCP 设置默认关闭；缺失设置也按关闭处理，不能从“host 存在”“曾尝试连接”或当前无条件连接行为推导为用户已授权。
- 只有用户主动启用业务桥接后才调用 `connectNative`。设置持久化，关闭后释放连接、取消已有重试，后台重启后仍遵守设置。
- 启用后 host 缺失或断开时，提供可理解的状态提示和受控重连；不能影响普通后台事件注册，不能恢复为默认每秒无限重试。
- 区分“默认不需要 host”与“禁止所有 nativeMessaging 能力”：发行包仍可保留可选业务桥接所需的 manifest 能力，但这些能力不能激活开发控制协议。
- 正式 Edge/Chrome 输出目录、版本与打包流程不因本地工作流而改变；host/Node 的安装步骤只列在开发说明及可选业务桥接说明中，不进入普通安装前置条件。

## 主动通知架构

```text
本地开发脚本
    ↕ 受限的本机 IPC
现有 Native Messaging host
    ↕ 已授权扩展的 Native Messaging 连接
同一份本地扩展后台
    → 校验开发会话与目标
    → runtime.reload()
    → 开发中继续使用 WXT HMR；退出后运行本地独立资源
```

### 控制协议与安全边界

- 复用 host 进程和 Native Messaging 能力，为开发脚本增加独立的受限本机入口；不要求 Codex MCP server 正在运行，不借用任意 MCP 客户端的普通请求通道授权重载。
- 本机控制入口限定当前用户权限，并验证每会话凭证、协议版本、请求类型、目标浏览器/扩展 ID 与会话标识。凭证不进入 Git、公开 manifest 或日志。
- 扩展侧开发控制处理器仅在本地自用构建启用。不得将开发重载作为通用 `tab_group.*` 工具暴露，发行包即使开启业务桥接也必须拒绝此控制消息。
- 会话或构建标识允许作为一次性消息元数据，用于幂等、确认与诊断；不再通过定期读取文件检测变化。
- host 对请求建立有限超时并返回结构化结果；扩展先确认收到合法切换请求，再执行重载，重载后的后台应报告新会话/运行模式，供工具验证完成。
- 文件发布成功、请求被接受、扩展完成重载是不同阶段。没有重载后确认时不得报告“已成功切换”。避免重载导致端口关闭被误报为普通成功响应。
- 不允许将 Node 执行、任意文件读写或任意扩展控制暴露给该入口。host 控制功能不得扩展普通发行扩展的信任范围。

## 固定安装目录与构建发布

- 优先保留现有 `.output/<browser>-mv3-dev/` 作为固定安装目录，避免只因换工作流而改变加载路径；实际 ID 稳定性需要浏览器验收，不能仅凭路径承诺。
- 开发与独立资源在隔离目录准备，最后成功的独立资源另存恢复副本。临时资源、会话凭证、socket 和日志不入 Git。
- 发布前校验资源完整与页面入口；替换失败时恢复上一个完整版本，不让浏览器通过通知加载半成品。
- 同目标的开发写入与恢复操作串行执行；WXT 仍可能重新构建后台或 manifest，因此需要协调 watcher、启动异常和配置变更，不能恢复后又被开发写入覆盖。
- 每个浏览器目标只允许一个拥有发布权限的会话，不能用另一个会话的进程或连接误判为本次切换成功。

## 生命周期

### 首次迁移

升级本地扩展和 host 后，需一次性重新加载扩展以启动新协议并重新建立 host 连接；如目标 ID 变化则重新授权。明确区分这次升级动作与此后每次启动开发，后者不得要求手动重载。

### 启动开发

1. 获得目标会话互斥权限，验证 host 注册、版本能力、连接目标与控制凭证。
2. 准备可恢复的独立版本；无历史成功版本且新构建失败时，不覆盖已有安装。
3. 在隔离目录准备开发资源，启动 WXT，等待服务与资源都就绪。
4. 完整发布到固定目录后主动通知目标后台重载。
5. 等待新后台的会话/模式确认，再报告已进入开发。后续页面修改继续 WXT HMR。
6. 必需 host 不可用或无法确认目标时，明确失败并保留/恢复可用独立版本，不静默要求手动点击、不退回轮询。

### 正常退出

1. 协调 `SIGINT`、`SIGTERM`、启动异常与重复退出请求，清理只执行一次。
2. 停止开发写入，暂时保留可用重载通道。
3. 在独立进程与目录构建最新独立版本，避免 WXT 进程内全局状态冲突。
4. 新构建成功则更新恢复副本；失败则明确报告并选择最后成功版本。
5. 完整发布独立资源后，通过受限 host 控制或尚存 WXT 连接主动请求重载；两者须遵守同一目标、幂等和完成确认约束。
6. 等待独立后台确认后关闭开发服务器；host 或确认失败时明确区分资源已恢复与浏览器尚未确认，不能假报成功。

### 强制中断与显式恢复

SIGKILL 或断电时不保证执行退出清理，也不保证强杀瞬间即可恢复。保留最后成功的独立资源，提供不启动开发服务器的恢复命令：恢复资源后通过 host 主动通知并确认重载。host 不可用时明确报告控制失败，正常标签管理不能被设计为必须依赖 host 才能运行。

## 测试与验收

### 开发控制与资源恢复

- 单元/进程测试：协议校验、会话认证、跨浏览器/ID 隔离、错误消息、超时、重复请求、防重载循环与未授权 MCP 请求拒绝。
- 发布测试：初次构建失败、末次独立构建失败、部分发布失败恢复、重复退出、并发会话拒绝与显式恢复。
- 无 MCP 会话时验证开发脚本仍能通知已连接的 host。
- Host 缺失、注册不匹配、协议过旧、切换中断连以及未收到后台确认时明确失败，不误报成功或静默换方案。
- 真实 WXT：开发资源入口仍由 Vite 转换，页面 HMR 不退化为每次完整构建。
- 隔离真实 Edge：连续启动/退出开发自动切换、浏览器重启后连接恢复、无需手动重载、无标记轮询或新增 alarm 权限；Chrome 单独验证。

### 发行边界

- 默认/缺失/关闭设置：后台启动和普通操作均不调用 `connectNative`，不创建重连任务。
- 开启可选业务桥接：有 host 时正常通信，缺失/断开时状态提示且普通功能继续可用；关闭时连接和重连全部停止。
- 显式启用状态持久化与后台重启恢复；旧版缺失设置不会默认为开启。
- 真实 Edge/Chrome 发行包产物检查：无开发控制处理器、监听入口、会话凭证、轮询模块与新增 alarm 权限；可选业务协议继续受独立授权约束。
- 无 host 的干净浏览器环境验证 popup/manager 与核心标签管理能力，不以源码检查替代实际功能验收。
- 用户现有 Edge 的安装 ID、偏好、真实页面 HMR 与退出后使用由单独验收记录确认，host 自动化测试不等于全部完成。
