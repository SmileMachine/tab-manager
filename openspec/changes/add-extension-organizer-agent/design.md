# Design：插件内 BYOK 标签整理 Agent

## 1. 范围与交互决策

Agent 作为 Current 工作区的右侧边栏存在，与左侧 Snapshot 导航栏使用相同的展开、收起和宽度调整模型。Current 顶栏提供右侧 Agent 的展开/收起按钮；Agent 边栏自身右上角提供设置按钮。Agent 不再占用内容区，也不再显示一次性 Analyze 面板。

Agent 采用会话式对话模型。用户可以连续发送多条消息，消息、助手回复和待批准的方案在当前 Manager 页面会话中保留。每一轮都将此前的非机密对话文本一并提交给模型，并重新读取当前浏览器快照；因此用户可以先让 Agent 查询或筛选，再要求解释、调整方案或执行。模型无法确定意图时应提出澄清问题，不生成写操作。

Agent 不提供任务 scope 选择。每轮默认面对所有符合条件的普通窗口标签页，跨窗口读取和整理属于普通能力。私密窗口、内部页面和页面正文仍按隐私规则排除；页面正文只有在设置中开启后才加入工具列表。

## 2. 权限决策

设置只保留两个与 Agent 能力相关的开关，避免把权限拆成难以理解的细项：

- `Allow Agent to read page content`：默认关闭。关闭时页面读取工具不进入模型工具列表，执行器也会再次拒绝伪造调用。
- `Allow automatic browser changes`：默认关闭。关闭时 Agent 只能生成待批准的整理方案，用户必须在对话中点击批准；开启后，经过本地校验的低风险写操作可以在当前轮自动执行。关闭标签、丢弃标签等高风险操作即使开启该设置，也必须由用户单独确认。

写操作的默认路径是“方案 -> 用户批准 -> 执行”。设置中的自动写入开关是用户对该类操作的一次性能力授权，不改变本地方案校验、浏览器版本检查、命令队列和失败报告。

## 3. Agent 运行时

继续使用 `ai` 的 `ToolLoopAgent` 与 `@ai-sdk/openai` 的 Responses 模型。每次用户发送消息时创建一次短生命周期 Agent，输入为当前会话消息和最新浏览器快照。工具包括：

- `read_tabs`：读取当前所有符合条件的标签页元数据；
- `search_tabs`：在当前快照中按标题、URL、域名、窗口或分组信息筛选；
- `inspect_page_content`：只在隐私设置开启时加入；
- `propose_plan`：生成经过本地校验的待执行方案，不直接写浏览器。

所有工具都使用最新快照建立上下文。方案绑定生成时的浏览器 revision；实际批准或自动执行时记录 revision 变化，但不因无关变化拒绝整份方案。执行器在每个 operation 前重新读取快照，缺失标签页、目标分组或窗口时只跳过对应 operation，其他 operation 继续执行，并将跳过与失败原因写入 console 和结果。执行过程继续使用后台共享命令协调器。Agent 不获得任意浏览器方法、脚本执行、导入、回滚或任意网络请求能力。

## 4. 布局实现

`WorkspaceShell` 扩展为可选的右侧边栏区域：

- 网格列为左侧 Snapshot 栏、主内容、右侧 Agent 栏；
- 左右边栏分别拥有独立宽度、收起状态和 resizer；
- 主内容保持自己的滚动容器，Agent 对话使用独立滚动容器；
- 右侧边栏未提供时，Snapshot/History 页面保持原有两列布局；
- 移动宽度下，右侧 Agent 进入主内容之后的独立行，并保留顶部开关。

Agent 面板负责对话状态、发送、取消、待批准方案和设置入口；WorkspaceShell 只负责布局，不持有模型状态。

## 5. 数据与生命周期

聊天记录以有界形式保存到扩展本地存储，不写入操作日志、导出或浏览器同步。不会保存 API key、页面正文或 provider 原始错误。刷新页面后恢复用户消息、助手消息、工具活动、错误和方案状态；进行中的请求标记为 interrupted。待批准方案继续绑定 plan hash、浏览器 revision 和配置身份，一次性确认有效期保持五分钟。
