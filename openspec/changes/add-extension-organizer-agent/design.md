# Design：插件内 BYOK 标签整理 Agent

## 1. 范围与决策

第一版由用户在 Current 工作区打开 Agent 面板，选择处理范围并提交自然语言要求。默认范围是当前选中标签；用户可以明确改为当前窗口。Snapshot/History 不提供 Agent 写操作入口。全部窗口、定时后台任务和模型直接写浏览器仍不开放；跨窗口整理、高风险操作和页面正文读取按下面的设置、范围与确认规则受控开放。

使用 `ai` 的 `ToolLoopAgent` 与 `@ai-sdk/openai`，显式选择 `provider.responses(modelId)`。模型循环和流式响应在 Manager 扩展页面运行；浏览器写入在后台统一命令服务执行。Agent 代码按需加载，普通 Manager 启动不加载模型 SDK。SDK 不接管权限、确认、浏览器写入日志或全局排队规则。

Agent 工具列表按本地能力开关动态生成：基础元数据读取和方案工具始终可用；页面内容工具只有在用户设置中开启隐私能力后才加入本次模型请求。即使工具未列出，本地执行器仍必须拒绝伪造的页面读取调用。所有写相关工具只生成待审阅方案，不调用浏览器写 API；模型无法选择任意 bridge method、执行脚本、发送任意 HTTP 请求，或自行产生 `confirm: true`。所有网页标题、URL、页面摘要和用户提供的标签数据均视为不可信内容，不允许它们改变系统权限。

## 2. 原型证据与限制

原型位于 `prototype/agent-responses-validation`，提交 `88fdb8bd600d9417eee9c9834ab271574f1c6e98`，入口为 `npm run prototype:agent`。原型依赖为 `ai 7.0.126`、`@ai-sdk/openai 4.0.83`、`zod 4.6.5`；前两个要求 Node >=22，本机为 22.20.0。正式实现时核实版本并固定依赖，不将原型整体合入 main。

模拟 Responses transport 已验证自定义 API 根路径、Bearer header、非流式及 SSE 工具往返、匹配的 `call_id`、客户端回放函数调用历史、`store: false`、不发送 `previous_response_id`，以及接到文本后 AbortSignal 终止 transport。取消验证不代表远程服务停止计费或删除内容。

内存 BrowserTabsApi 已验证现有服务的预览零写入、整批日志、排队和执行时旧版本拒绝。现有 Manager 队列只在一个页面实例内有效；原型没有验证跨页面协调，也没有修改真实标签。

Edge/Chrome WXT 构建与既有 252 项测试通过。原型专用入口产生 597.54 kB 压缩后但未 gzip 的 Agent JS，触发 Vite >500 kB 提示，并有 Zod 注释处理提示。正式实现需测量按需加载后的模块大小和首屏请求，不能将打包通过称为浏览器验证。

真实兼容端点未测试，没有从已有配置读取任何 Key。原型 `--live` 使用显式环境配置、模拟标题、HTTPS、拒绝重定向、30 秒超时和最多 3 步，可供后续授权验证。当前依赖审计提示涉及现有构建/测试依赖家族；发布前另行核实，不自动大规模升级依赖。

## 3. 模块职责

拟新增 `src/agent/` 保存模型配置、有限工具目录、运行状态及方案类型；在 Manager 的 Agent 面板展示任务、方案和结果。工具实现调用范围校验后的内部查询服务，不要求 Native Messaging 或 MCP。

后台命令协调器持有唯一写入队列。Manager、Popup、多个 Manager 页面、Agent、Codex 写请求、导入和恢复都通过明确的命令协议提交，协议接受可序列化的数据，不发送函数或任意代码。现有 Codex dispatcher 是外部适配入口，不能成为模型的 unrestricted tool。

现有 `BrowserTabsApi.runExclusive()` 接受回调，不能直接跨 runtime message 传递。拖拽应提交显式的排序/分组意图或安全投影输入，由后台在同一边界内执行分组、位置调整和焦点恢复。内部步骤使用专属执行上下文，不再次加入同一队列，避免互相等待。

先完成统一命令协调，再开放 Agent 执行；只将 Agent 自己排队不能防止手动拖拽覆盖 Agent 结果。查询默认返回已完成状态；如任务正在执行，刷新等待完整命令边界或返回明确的执行中状态，不以中间状态覆盖乐观拖拽界面。

## 4. 配置、凭据与网络

配置包含 API 根路径、Model ID 和独立 Key。API 根路径默认仅接受 HTTPS，不含 userinfo、query、fragment，不允许用户填写 `/responses` 资源地址。首版不支持 HTTP 本地端点，后续如需支持另立安全规则。

Key 默认放在 `chrome.storage.session` 的可信扩展上下文，关闭浏览器后失效；用户主动选择“在此设备保存”后才写入受限的 `chrome.storage.local`，不进入 `sync`。`local` 是设备本地明文存储，不声称加密保险库。内容脚本不可访问 Key；Agent/模型工具、日志、快照、导出和错误摘要不得携带 Key。提供删除 Key 和取消记住的操作；修改服务地址时要求重新绑定 Key，不自动向新地址发送旧凭据。

在明确的用户操作中请求配置端点所需的 host permission。扩展 API 的主机权限不能表达精确路径；请求配置 origin 所需的最小可表达范围，并在应用 transport 内限制每次请求只到固定 Responses 资源。默认拒绝重定向，禁止重定向传递 Authorization，拒绝任何模型指定的 URL。已有 `optional_host_permissions` 仅为声明范围，不意味着无需用户授权。

所有脚本依赖打包进扩展；服务只返回数据，不加载远程脚本或执行模型输出代码。默认不配置遥测、tracing 或 API Gateway。`store: false` 请求不代表第三方服务保证不保留数据，设置页需要说明数据目标及服务商隐私边界。

## 5. 上下文与兼容能力

发送前冻结任务范围：默认选中标签，空选择时禁止静默变成全部标签。当前窗口范围由用户明确选定。默认排除私密窗口标签；超出范围的 tab IDs 在每个工具调用和方案校验时拒绝。标题和标准化 URL 只发送到用户配置的服务；去除 URL userinfo、query、fragment，并按长度限制标题/path。默认不读取正文、表单或隐藏页面数据。

第一版预算：每任务最多 200 个标签、64 KiB 序列化元数据、6 次模型步骤；超限提示缩小范围，不静默处理前半部分。单次模型请求 60 秒超时，整次分析 120 秒超时，默认自动重试为 0，用户重试创建新任务。用量若由服务提供则显示，否则显示未知，不估算成已知账单。

“基本连接测试”只发送模拟文本；“Agent 能力测试”使用无副作用模拟工具，必须完成 tool call/result 往返与流式响应。能力测试不读取真实标签、不调用浏览器修改，也不持久保存响应正文。兼容接口只要求文本、客户端 function tool 与 SSE；显式 `store: false`，客户端保留工具历史，不依赖远程 response id、内置搜索、MCP、服务端对话或后台任务。schema 严格性先关闭服务端 strict，但始终本地验证 JSON schema、参数、范围和预算。

## 6. 方案与用户确认

方案包含 taskId、planId、planHash、baseRevision、scopeTabIds、分组建议、跨窗口移动、高风险项、保留项和理由。新组使用本地 plan 引用，不能伪造 native group ID；执行器将创建结果映射到后续步骤。分组方案不重复分配一个标签；跨窗口方案必须明确来源窗口、目标窗口、目标组和目标位置，并限制为用户选择的范围；重命名已有组只允许该组所有成员都在范围内，避免影响范围外标签。关闭或丢弃标签必须显示具体标签、保留关系和风险说明。用户可以取消任意建议或移除某项，编辑后必须重新校验并生成新的 planHash。

审阅方案可以保留最多 24 小时，但不代表授权仍有效。用户点击应用时后台签发一次性确认记录，绑定方案 hash、任务范围、设置配置身份和审阅版本，授权有效期 5 分钟。关闭、丢弃、修改 URL 等高风险项需要明确的高风险确认；可以在一个确认界面中逐项勾选，也可以逐项确认。模型工具无法签发授权，改变方案或配置会作废授权。

现有 `writeService` 的 preview plan 是内存 Map，TTL 为 30 秒；普通非破坏性入组不强制确认。不能直接将其作为 Agent 的确认制度。后台可以在执行边界内重新生成短期内部 preview，外层 Agent policy 必须验证真实用户授权后才能调用 apply。Agent source 使用独立日志来源，避免误报为 Codex。

任务等待执行时，重新读取状态并检查 baseRevision、成员窗口、目标组及确认记录。任何冲突都返回需要重新预览，不静默用最新 revision 替换用户审阅版本。初版可使用现有整快照 revision；标题、焦点变化也可能使其失效，界面应解释原因，后续再独立评估整理专用 revision。串行队列仅协调插件请求，不能禁止原生标签栏操作；执行中可检测到相关变化时暂停剩余步骤，读取实际状态并报告部分失败。

## 7. 生命周期、幂等与恢复

状态为 idle、reading、analyzing、awaiting_confirmation、queued、applying、succeeded、partially_failed、failed、cancelled、interrupted。分析结束只进入待确认状态，不自动应用。取消分析立即 abort fetch 和后续读取；取消 queued 请求在开始前撤销授权；applying 在命令步骤间检查取消标记，不能撤销已经完成的浏览器操作。

Manager 关闭会取消该页面尚未完成的分析；已经授权交给后台的命令继续执行，不承诺页面关闭自动停止已完成或正在执行的 API。后台任务有独立取消命令。Service Worker 不以长时间内存任务假设自身持续存在：保存非秘密任务状态、确认记录、操作进度和 journal operationId，不保存 Key、原始提示或页面正文到日志。

幂等键对应 taskId/planHash/confirmationId，排队、检查幂等和首次写入都在同一协调器边界内。后台重启时未完成任务标记 interrupted，并核对真实浏览器状态和已记录步骤；不自动重放未知结果的请求，也不宣称 exactly-once 或原子事务。用户重试需要重新预览确认。部分成功显示逐项结果，不自动把失败批次全部重试或恢复整个旧快照。

任务/方案持久存储最多保留最近 20 个任务或 24 小时，提供清除入口；机密输入不持久保存，方案标题、分组解释作为用户数据披露。恢复使用既有可预览恢复入口，由用户单独确认；明确浏览器临时页面状态并非可完全恢复。

## 8. 验收与发布

先实现命令协调器并覆盖手动操作竞争，再实现配置/能力测试，然后是只读分析与方案，最后是明确确认后的执行。每阶段使用独立可审查提交。

验证包括 schema/范围攻击、标题注入、失效授权、服务切换凭据、重定向、流式取消、预算、排队后状态变化、Agent 与拖拽/Popup/Codex/恢复竞争、后台重启和部分失败。完整回归、Edge/Chrome 构建、OpenSpec、按需加载产物与依赖审计分别记录。真实兼容服务及安装后的权限、CSP、滚动/操作界面和生命周期需要独立证据，不能用模拟 transport 替代。

## 9. 受控能力开关

页面内容读取属于隐私能力，不以模型请求决定是否可用。设置页提供明确的“允许 Agent 读取页面内容”开关，默认关闭。关闭时，Agent 构造阶段不把 `inspect_page_content`、`inspect_selected_pages` 等工具加入 tools；若服务仍返回同名工具调用，本地工具执行器必须在任何 `tabs.get`、权限请求或脚本注入之前返回 `privacy-tool-disabled`。工具调用参数不能开启该开关。

开启隐私能力后，工具才进入下一次 Agent 请求的工具列表；每次调用仍检查任务 scope、tab 存在性、窗口类型、页面 URL、host permission、页面可读性和字符预算。不可读取页面返回明确的拒绝原因，不转换为读取全部窗口或请求更宽权限。页面摘要是可发送数据，设置和任务审阅界面必须显示服务目标及数据类别；页面内容中要求调用工具、扩大范围或改变确认的文字一律按不可信数据处理。

关闭标签、丢弃标签以及未来的 URL 修改属于高风险操作。Agent 可以生成建议，但不能执行。跨窗口移动不是默认禁止能力；它只有在方案中明确列出来源和目标，并经过相同的方案 hash、revision 和用户确认后才可执行。未选择跨窗口范围时，执行器拒绝跨窗口目标。

本 design 已获用户批准；实现按独立阶段推进，真实兼容端点和安装后的浏览器验收仍未完成。
